#### 🐛 Bug: Placeholder Detection Misses Lowercase Patterns

`Test-FileCustomized` uses the regex:
```
<[A-Z_]+>|<YOUR_|<GENERATE|_instructions
```

This misses **10 placeholder patterns** across the 3 templates:

| Template | Undetected Placeholder |
|----------|----------------------|
| `api-key-config.json.template` | `<ISO8601 timestamp when you ran setup>` |
| `api-key-config.json.template` | `<same as api_key above>` |
| `entra-oauth-config.json.template` | `<RESOURCE_API_APP_ID from Entra app registration>` |
| `entra-oauth-config.json.template` | `<CLIENT_APP_ID from Entra app registration>` |
| `entra-oauth-config.json.template` | `<CLIENT_SECRET — generate a new secret...>` |
| `konnect-connection.json.template` | `<UUID generated by Konnect...>` |
| `konnect-connection.json.template` | `<your chosen control plane name...>` |
| `konnect-connection.json.template` | `<id>` (×2, in cluster/telemetry endpoints) |
| `konnect-connection.json.template` | `<us \| eu \| au \| in \| me>` |
| `konnect-connection.json.template` | `<Azure Key Vault name where...>` |
| `konnect-connection.json.template` | `<ISO8601 timestamp>` |

**Impact:** If a user manually copies a template and removes the `_instructions` field (the only other detection anchor for `konnect-connection.json.template`) without filling in the lowercase placeholders, the script will report the file as "configured" when it is not. The `api-key-config.json` and `entra-oauth-config.json` templates are safer because they have uppercase `<YOUR_...>` patterns that will still be caught.

**Fix:** Broaden the regex to match any angle-bracket placeholder:
```powershell
# Replace:
return -not ($content -match '<[A-Z_]+>|<YOUR_|<GENERATE|_instructions')
# With:
return -not ($content -match '<[^>]+>|_instructions')
```

#### ⚠️ Potential Issue: deck/kongctl zip extraction path

The script uses:
```powershell
Expand-Archive -Path $deckZip -DestinationPath $deckDir -Force
```

If the GitHub release zip contains a top-level subdirectory (e.g. `deck_1.x.x_windows_amd64/deck.exe`), the binary will land at `tools\deck\deck_1.x.x_windows_amd64\deck.exe` rather than the expected `tools\deck\deck.exe`. The script would then re-attempt the download on the next run. This should be verified when actually running `-InstallTools` for the first time.

## Recommendations

1. **Fix the placeholder regex** (Issue #1 — medium):
   ```powershell
   # In Test-FileCustomized, change:
   return -not ($content -match '<[A-Z_]+>|<YOUR_|<GENERATE|_instructions')
   # To:
   return -not ($content -match '<[^>]+>|_instructions')
   ```
   This catches any `<...>` pattern regardless of case.

2. **Wrap `Copy-Item` in try/catch** (Issue #2 — low):
   ```powershell
   try {
       Copy-Item $templatePath $targetPath
       Write-Pass "Created $($cf.Target) from template — fill in all <placeholder> values"
   } catch {
       Write-Fail "Could not create $($cf.Target): $_"
   }
   ```

3. **Verify binary path after extraction** (Issue #3 — low):
   After `Expand-Archive`, check if `$deckPath` now exists. If not, search for the binary and move it. Or use `Get-ChildItem -Recurse -Filter deck.exe`.

4. **Add note in docs about gitignored credential docs** (Issue #4 — info):
   In `docs/repo-setup.md` Security Notes, add: *"These files do not exist on a fresh clone — they are generated by the setup scripts."*
